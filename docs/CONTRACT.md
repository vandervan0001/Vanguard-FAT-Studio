# Internal implementation contract — FAT Studio 0.1.1

This document records the 0.1.1 contract. Later project fields, guided FAT execution, analog stimuli, pulse controls and the local assistant CLI are described in [AI_CONTROL.md](AI_CONTROL.md). Query `/api/health`, `/api/openapi.json`, `/api/schema` and `/api/catalog` on the running instance before building a client. Historical contracts and test results do not establish the current Siemens qualification status; see [ETAT_REPRISE.md](codex/ETAT_REPRISE.md).

Package `fat_studio`, Python 3.12+, FastAPI. UI React/TypeScript/Vite + React Flow. All routes same-origin under `/api`; server serves bundled UI. Target Windows, portable demo Linux/macOS. Model is deterministic, no controller when OPC UA is selected.

## Project JSON

`schema_version: "1.0"`, `id` (safe slug), `name`, `description`, `simulation: {step_ms:100,speed:1}`, `equipment: Equipment[]`, `connections: Connection[]`, `tags: Tag[]`, `scenarios: Scenario[]`, `plc: PLCConfig`.

Equipment: `{id,type,name,description,unit,position:{x,y},params:{...},bindings:{port:tag_id}}`. Types: `tank,pump,valve_onoff,valve_control,analog_sensor,digital_sensor,indicator`. Ports and parameters advertised by GET `/api/catalog`. Connections `{id,source,target,label,directed}`. Explicit flow groups use `params.tank_id`, `params.role` (`inlet`/`outlet`), `params.flow_group` on pumps/valves. Series devices in one flow group limit the flow to its minimum; independent groups add. Graphical lines do not infer a general hydraulic solver; show this in UI.

Tag: `{id,name,direction:"input"|"output",data_type:"BOOL"|"INT"|"DINT"|"REAL",unit,initial_value,min,max,node_id,writable}`. `input` means simulated sensor written TO PLC, `output` means PLC command read FROM PLC. No direct command writes in real mode. Missing node_id is acceptable in demo; invalid in OPC UA. `writable:true` required for input writes.

The Project schema remains `1.0`. REAL values are normalized to finite IEEE-754 Float32 by tag validation, including initial values, forces, published measurements and command images. Internal plant calculations remain Float64. Representable REAL engineering bounds are quantized to the same format before comparisons, quality classification and out-of-range fault validation. For example, `16777217` is stored as `16777216`; a limit of `0.1` accepts its Float32 representation `0.10000000149011612`. JSON roundtrips may therefore expose more decimal digits than the original input. No boolean, NaN, infinity or value outside the REAL storage range is accepted as a REAL.

PLCConfig: `{mode:"demo"|"opcua",endpoint:"opc.tcp://127.0.0.1:4840",expected_application_uri:"",namespace_uri:"",security_policy:"None"|"Basic256Sha256",server_certificate_sha256:"",client_certificate:"",client_private_key:"",username_env:"",password_env:"",approved_virtual_target:"",timeout_s:3}`. Local virtual adapter IP allowed only by local machine policy, never by project self-authorization. Live target requires explicit confirmation on start. Do not fabricate Siemens identity.

Scenario: `{id,name,description,duration_s,steps:[{at_s,action,target,value,operator,tolerance,message}]}`. Actions `force,release,fault,clear_fault,marker,expect`. Fault target equipment id; fault value `{kind,value?}`. Expect target tag id; operator `eq,ne,gt,ge,lt,le`; tolerance numeric. Evaluation uses fresh completed model step. Keep per-step result in log. End of duration pauses, never restarts.

Numeric `eq`/`ne` assertions use the supplied absolute tolerance with zero relative tolerance. Ordering comparisons do not apply this tolerance. The expected value remains the user-supplied value; it is not silently normalized to make an assertion pass. A zero-tolerance decimal expectation can differ from its Float32 signal.

## Engine Python

`models.py` defines Pydantic models Project, Equipment, Tag, Scenario and validation. `catalog.py`: CATALOG list JSON dictionaries describing types, labels, default params, bindings/ports. `demo.py`: `demo_project() -> Project`. `engine.py`: `ProcessEngine(project)` with `reset()`, `step(commands:dict,dt:float)->dict[tag_id,value]`, `force(tag_id,value)`, `release(tag_id)`, `set_fault(equipment_id,kind,value=None)`, `clear_fault(equipment_id,kind=None)`, and attributes `values`, `equipment_state`, `forces`, `faults`, `time_s`. `DemoController(project)`: `read_commands(values,dt)->dict`, `reset()`. Expose `validate_project(project)->{valid,errors:[{path,message}],warnings:[{path,message}]}`. Model engine never imports adapters.

Sensor validation checks known source ranges after scale/offset and any integer rounding. Tank inflow/outflow ranges account for series minima and parallel sums. Cumulative overflow has no finite upper bound in an unlimited manual run: validate its zero-origin value including offset, warn when its scale is nonzero, and fail on a later storage overflow. A failed `step` restores the pre-call time, equipment state, raw/published values and qualities together. It does not undo actions performed before the call, or any subsequent OPC UA effects. Demo level control fills low tanks through inlets and drains high tanks through outlets; constant commands remain explicit.

## OPC UA connection boundary

Every connection rechecks machine authorization and the exact target confirmation. Basic256Sha256/SignAndEncrypt uses the pinned server certificate and validates its time window and SAN application URI. The identity returned by `CreateSession` is checked before `ActivateSession` can send username/password credentials. Missing or rejected credentials do not trigger anonymous fallback. These checks do not implement a CA trust store, CRL/OCSP lookup or general DNS identity validation; machine pinning remains the trust decision.

Namespace 0 is forbidden both in a raw mapped NodeId and as the result of resolving `namespace_uri`. Node existence, scalar rank, types, effective rights and duplicate resolved identities are checked before writes. A bad/incomplete read, malformed live value or failed/partial write latches the connection as unavailable. OPC UA batches are not atomic; acknowledged partial writes cannot be rolled back by the process engine. The OPC UA server's Running state is a transport diagnostic, not proof that a Siemens CPU is in RUN.

## API

GET `/api/session` => `{token}` for X-FAT-Token header on mutation. UI requests it at boot. GET `/api/health`. GET `/api/catalog` list. GET `/api/project` => Project. PUT `/api/project` Project => Project (validate/save/update idle engine). POST `/api/project/import` Project => Project. GET `/api/project/download` JSON attachment. POST `/api/projects` `{name}` => empty new Project/current. GET `/api/projects` => `[{id,name,updated_at}]`. POST `/api/projects/{id}/load` => Project. POST `/api/demo/load` => demo Project. GET `/api/validate` => validation above. GET `/api/mapping` CSV; POST `/api/mapping` `{csv:string}` => Project.

GET/PUT `/api/project` and successful import/create/load/mapping responses include `X-FAT-Project-Revision`, the SHA-256 of the returned Project's canonical JSON (sorted keys, compact separators, UTF-8). The download attachment is separate. The UI stores this baseline only after a successful Project response, never from state polling. It sends both `X-FAT-Project-ID` and `X-FAT-Project-Revision` on PUT `/api/project`, POST `/api/mapping`, and mutations under `/api/run/`, `/api/force`, `/api/fault`, `/api/markers` and `/api/result`. The server compares supplied context under the mutation lock and returns 409 on a mismatch, before acting. The UI preserves the local draft and requires a reload. These context headers remain optional for other API clients; omitting them gives no protection against a stale project or concurrent overwrite. `X-FAT-Token` remains mandatory for every mutation. Explicit import/create/load routes select a project and are not guarded by the previous project's revision.

Run mutations also accept `X-FAT-Run-ID`. When supplied, it must equal the current runtime `run_id`, or the empty string when the runtime has no run. An empty header therefore asserts **no current run**; an omitted header skips this check for compatibility. The comparison occurs under the same API mutation lock and a stale value returns HTTP 409 before any run command, force, fault, marker or verdict is applied, including when a new run uses the same project revision. The UI supplies this run context. GET `/api/mapping` also checks any supplied project ID/revision under that lock; run context does not apply to mapping exchange.

GET `/api/state` => Snapshot. POST `/api/run/start` `{scenario_id?:string,target_confirmation?:string}`. POST `/api/run/{pause,resume,stop,reset}`. POST `/api/force` `{tag_id,value}`; DELETE `/api/force/{tag_id}`. POST `/api/fault` `{equipment_id,kind,value?}`; DELETE `/api/fault/{equipment_id}` clears all. POST `/api/markers` `{message}`. POST `/api/result` `{verdict:"pass"|"fail"|"not_evaluated",comment:string}`. GET `/api/export/csv`, GET `/api/export/report` HTML attachment; GET `/api/export/json` full evidence. GET `/api/runs` lists archived reports, GET `/api/runs/{id}/csv|report|json`.

Snapshot: `{project_id,project_revision,status:"idle"|"running"|"paused"|"stopped"|"error",sim_time_s,wall_time,run_id,connection:{mode,connected,target,quality,last_update,error},tags:{[id]:{value,quality,forced}},equipment:{[id]:{...}},faults:{[id]:{[kind]:value}},events:[{id,timestamp,sim_time_s,kind,message,details}],series:[{time_s,values:{[id]:value}}],result:{verdict:"pass"|"fail"|"not_evaluated",comment:string},scenario:{id,state,completed_steps,total_steps,assertions:[]},error,write_count,lag_ms,model_warnings}`. Poll state every 500ms. Mutation returns current snapshot except project endpoints. Error `{detail: string|object}`; display meaningful error.

`result` is always present and starts as `{verdict:"not_evaluated",comment:""}` for a new run or reset model. Saving a verdict updates `runs.result_json` and inserts its `user_result` event in one SQLite transaction. The runtime changes its in-memory result and appends the returned event only after that transaction succeeds. A failed event insert therefore cannot leave a new verdict without its audit event; an active run also follows storage fail-stop handling.

### Mapping CSV

New exports contain these eleven columns, with `_fat_csv_encoding` set to `apostrophe-v1` on every row:

```csv
id,name,direction,data_type,unit,initial_value,min,max,node_id,writable,_fat_csv_encoding
```

Only `name`, `unit` and `node_id` use reversible text escaping. Prefix one apostrophe when the original text starts with an apostrophe, or when its first non-whitespace character is `=`, `+`, `-` or `@`. An original leading apostrophe is consequently doubled. The importer removes exactly that added character when the marker is present, validates the escape and rejects an unknown marker. It accepts a leading UTF-8 BOM. Legacy files with the original ten columns remain accepted literally: no leading apostrophe is removed from them. `initial_value` remains JSON, empty min/max cells mean no bound, and `writable` is exactly `true` or `false`. Numeric negative values are not escaped. Unknown/duplicate headers, wrong column counts, invalid tag types and duplicate IDs are rejected.

Exports capture run metadata and append-only sample/event ID limits in one SQLite query before sending response headers. JSON includes `snapshot:{captured_at,last_sample_id,last_event_id}`; `captured_at` is UTC and `sample_count` matches the exported samples. CSV/JSON stream only records at or below those limits through a dedicated read-only connection. An export requested during a run is therefore a finite snapshot, excluding later cycles and events; the HTML report shows its capture time. Streaming does not load all samples into memory.

If evidence storage fails, the runtime stops further exchanges, disconnects and exposes the error even if recording that error also fails. In that case the in-memory error event has `details.persisted:false`. It is not a durable record: a full or inaccessible disk can prevent final samples, events or terminal status from being saved. Previously committed evidence remains available; the UI must not present an in-memory fallback as a successfully archived event.

Independent cancellation of startup, an exchange cycle or the running task is also fail-stop: close the connection, set the run to error, mark the current image `bad`, and attempt to record that terminal evidence. No automatic reconnect occurs. Cancellation during a network write can leave the last batch partly applied or its outcome unknown; a recorded calculated image is not a receipt for every server write. Normal pause/stop use the runtime lock to finish the active cycle before returning and detach the loop before cancelling its wait. A cancelled transition itself is treated as an error.

Editing is locked while running or paused; stop then edit. Persist explicitly with Save; warn on dirty navigation. Run Start first saves project, validates mapping then starts. Forcing exclusively simulated inputs; demo controls run inside DemoAdapter, not in plant. No tool downloads or sets CPU RUN/STOP.
