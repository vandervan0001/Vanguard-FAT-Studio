# Version 0.4.0 : tags, débits et réutilisation

## Fonctions livrées

Le collage de cellules Excel et les fichiers CSV/TSV passent par une revue des colonnes puis des variables. Les séparateurs, titres, types et sens peuvent être choisis explicitement. Une erreur de ligne bloque l’application entière. La fusion utilise les identifiants ; elle conserve les champs absents et les contrats des variables utilisées. Les classeurs `.xlsx` ne sont pas lus directement.

La fenêtre **Comprendre le débit** montre les faits du dernier cycle du moteur : commande, position ou vitesse, capacités des organes en série, organe limitant et disponibilité de la cuve source. Les données historiques sont datées. Une qualité indisponible, une erreur ou un modèle modifié empêche leur présentation comme explication actuelle. Aucun interverrouillage interne du PLC n’est déduit.

**Mes cibles sur ce poste** réutilise les identités déjà autorisées par la politique locale. Le choix prépare un brouillon ; le contrôle de connexion reste volontaire et ne lit ni n’écrit de valeurs de procédé. L’identité et le certificat sont vérifiés avant l’authentification. Ce contrôle ne qualifie pas le mapping.

**Mes circuits** conserve jusqu’à 20 modèles dans le navigateur. L’export/import JSON permet de les transférer. Les copies reçoivent de nouveaux identifiants et des adresses automate vides ; leurs liaisons internes sont conservées. La connexion, les scénarios et les preuves d’essais sont exclus des modèles.

La comparaison des brouillons utilise leur version de départ, la version enregistrée et les modifications locales. Les conflits demandent un choix individuel. L’application est précédée d’une validation et ne fait qu’éditer le brouillon. Les notes et observations FAT restent dans la sauvegarde d’origine téléchargée ; aucun résultat d’essai n’est fusionné.

## Vérification et reproduction

La suite Python locale Windows a réussi : 675 tests, 8 ignorés. Cinq cas ignorés nécessitent les droits de liens symboliques, deux un clone amont TIA déclaré et un concerne uniquement POSIX. La CI exécute les contrôles avec la source amont épinglée sur Windows et Ubuntu. Les tests navigateur couvrent les nouvelles fonctions, les conflits de contexte, la conservation des données, le clavier et les fenêtres à 768 pixels.

Commandes : `python -m pytest`, `python -m ruff check fat_studio integrations tests scripts`, puis, dans `frontend`, `npm ci`, `npm run build` et `npm test`. Copier les assets avec `python scripts/build-web.py` avant de vérifier le service livré. Les dépendances sont verrouillées ; le format de projet reste 1.0.

Les résultats définitifs du portable extrait, son empreinte, la source exacte et la CI figurent dans le reçu de la [release 0.4.0](https://github.com/vandervan0001/Vanguard-FAT-Studio/releases/tag/v0.4.0). Une construction propre et le manifeste identifient le contenu distribué. Les données de qualification sont isolées et les notes locales sont exclues de la sélection publique. Aucun automate réel n’est qualifié par ces essais.
