# Sélection V20/V21, dépôt privé et arrêt du serveur

Date : 2 novembre 2026, macOS 26.3.1 ARM64. Demandes de Tai : publier le projet dans un Git privé, arrêter le serveur local, puis adapter la préparation à TIA V20 et permettre le choix V20/V21 avant publication.

## Référence et travail effectué

Point de départ : `1054d96d28bc2edb47f5ad8f2cbb742f6b2828da`, branche de travail `codex/tia-v20-v21`. Copie source préservée avant édition dans le scratchpad de `../work/2026-11-02-v20-v21`. Le kit Windows original et ses preuves 0.1.1 n'ont pas été modifiés.

La version applicative est passée à 0.2.0. Le champ `plc.tia_version` accepte V20/V21, avec V21 par défaut pour les anciens projets. Le sélecteur Connexion est enregistré/exporté/importé et verrouillé pendant l'essai. Le guide adapte suffixe de projet et commande d'installation. Les profils d'ingénierie lient la version aux binaires installés, aux DLL réelles et à leur environnement, aux propositions, acquittements, audits, reçus et archives.

V21 utilise le paquet Czarnak 4.3.0. V20 prépare un portage de la source épinglée et demande un build Windows contre les DLL V20 réellement installées. Le worker et le host sont restaurés séparément et reçoivent la version 4.3.0 attendue. Aucun serveur préexistant non marqué, référence factice ou repli V21 n'est admis. Les clients IA restent en lecture seule ; l'application des modifications conserve les confirmations humaines.

La relecture a fermé les défauts suivants : admission ambiguë d'un exécutable non marqué en V21, absence de propagation du dossier Openness, restauration manquante du worker et version produit non injectée au build source. Un défaut de packaging reproduit conservait un ancien JS haché dans `build/lib` ; `build-web.py` nettoie maintenant seulement son cache web borné, avec contrôles de liens avant mutation. La wheel finale ne contient plus cet asset. Les causes et invariants figurent dans [KB.md](../../../KB.md).
